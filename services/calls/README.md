# Голосовые поручения — отдельный сервис Pipecat

Добавлен браузерный режим **Flows + Gemini Live** с настоящим FlowManager, переходами через результаты инструментов и проверкой новой речи перед отбоем. Область поддержки и сценарии проверки описаны в [LIVE_FLOWS.md](LIVE_FLOWS.md). Телефонные подключения используют прежний исполнитель до отдельной проверки.

Замеры скорости обычной цепочки с отдельными распознаванием, текстовой моделью и голосом: [BENCHMARKS.md](BENCHMARKS.md).

Отдельный Pipecat сервис: поручение → выбранные факты AnyMsg → Gemini Live → консультант → отложенный вопрос владельцу → новое продолжение. Добавлен серверный пилот: Telegram signaling через существующий session owner, Twilio для WhatsApp Business, телефона и SIP, отдельный MCP с 14 tools. Telegram connection проверен; живые звонки ещё не выполнены, Twilio credentials/Business sender требуют настройки. Сервис запускается независимо; состояние передаётся через `VOICE_DATA_DIR`. Подключение провайдеров выполняет владелец.

## Запуск

Из этой папки:

```sh
uv sync --locked --python 3.13
cd frontend
npm ci
npm run build
cd ..
uv run python app.py
```

Открыть **http://127.0.0.1:13842/**. Браузер запросит логин `owner` и пароль из `VOICE_DATA_DIR/owner.token`, созданного сервисом при первом запуске. Сервер слушает только loopback; для удалённого доступа используйте SSH tunnel, не публикуйте панель через обычный HTTP. Python 3.13, Pipecat 1.12.0, Gemini `gemini-3.8-live`, SmallWebRTC. Это native audio: отдельные ASR/LLM/TTS сервисы не добавлены. LiveKit не подключён.

Кнопка **«Подключить Gemini»** принимает ключ из [Google AI Studio](https://aistudio.google.com/apikey). В новый процесс ключ нужно ввести отдельно; он не переносится из Voice Lab. При обычном локальном запуске ключ хранится только в памяти и удаляется после перезапуска или кнопкой «Удалить ключ». Серверная установка с VOICE_PERSIST_CREDENTIALS=1 сохраняет его в приватном файле; это явно показано в setup panel. Сохранение ключа не доказывает доступ к модели: API проверяется при разговоре. Аудио и выбранный контекст передаются Gemini; raw audio локально не записывается.

## Первая проверка

1. Оставить учебное поручение о заказе TEST-104 или заполнить своё. Выбрать русский, английский либо индонезийский, голос и формы самопрезентации.
2. При необходимости раскрыть «Добавить сообщения AnyMsg», выполнить адресный поиск и отметить до 8 сообщений. Голосовой агент не может искать по всему архиву сам.
3. Нажать **«Подготовить поручение»**, прочитать факты и точные инструкции. После изменения настроек нужен новый snapshot.
4. При необходимости задать «Дополнительный контекст для консультанта». Его получает отдельный текстовый Gemini Flash при `consult_supervisor`, не голосовой prompt напрямую. Это отдельный API-запрос на том же ключе.
5. Начать разговор и играть собеседника. Сообщить доставку 11–12, исправить на 12–13 и назвать доплату 50000 IDR. Не отвечать владельцем во время разговора: ассистент должен сохранить запрос и кратко закончить с `needs_owner`, не обещая неподключённый обратный звонок.
6. После завершения в «Вопросы, которые можно решить позже» ответить «Отклонить», затем нажать «Подготовить продолжение в браузере». В новой попытке агент передаст отказ. Предложить 25000 IDR или попросить пересмотреть: нужен новый запрос, прежний ответ не распространяется на новые условия.
7. Оценить каждую попытку и повторить на остальных языках. История сохраняет snapshots, текст, tools, советы, решения и связи продолжений.

Подсказка с тестовыми ответами в браузере **не входит** в инструкции модели. Задержка p50/p95 приблизительная: конец звука микрофона → начало звука ответа, один монотонный браузерный таймер; приветствие и реальное наложение речи исключаются. Фоновые звуки, паузы, устройство вывода и малое число измерений влияют на результат. Значения без измерений пустые.

Проверять отдельно: собраны ли нужные поля; учтено ли исправление; не обещана ли неподтверждённая оплата/бронь; выполнены ли нужные tools; сохранилась ли естественность; можно ли перебить; задержка. Успех транспорта или синтетического теста не считается оценкой Gemini на ru/en/id.

## Контекст AnyMsg

В рабочем окружении локальная настройка находится в ignored `.local/voice-service/anymsg.json`. Для другой установки можно задать `VOICE_ANYMSG_CONFIG` с JSON:

```json
{"base_url":"https://your-anymsg.example/prefix","token_file":"/private/path/anymsg.token"}
```

`base_url` — корень REST API без `/mcp`; файл содержит Bearer token без префикса. Файлы должны быть доступны только владельцу. Сервис не читает messenger session/profile и не запускает collectors. Используются только `POST /v1/capabilities`, `/v1/search`, `/v1/get_context`. Рекомендуется отдельный AnyMsg principal только с правами чтения.

Поиск ограничен 12 результатами. При подготовке каждый выбранный anchor читается с `before_count=0`, `after_count=0`; соседние сообщения, вложения и reviews не включаются в prompt. Удалённый/недоступный источник останавливает подготовку. В snapshot сохраняются ID, ревизия, аккаунт, чат, дата, конфликт и признак сокращения текста. Архивные сведения остаются наблюдениями, не проверкой текущего состояния у провайдера. Ошибка чтения не подменяется пустым успешным ответом.

## Инструменты внутри разговора

| Tool | Действие |
|---|---|
| `lookup_context(query)` | Прочитать только факты текущего snapshot; пустой запрос возвращает все выбранные факты |
| `record_answer(field, value, evidence)` | Сохранить/исправить разрешённое поле с цитатой; для `approval_fields` автоматически создаёт запрос решения и возвращает его состояние |
| `request_owner_decision(question, options)` | Создать запрос, включая пересмотр тех же условий после ответа; повторный вызов при уже ожидающем решении возвращает тот же раунд |
| `consult_supervisor(question)` | Краткий совет отдельного Gemini Flash; выбранные факты, дополнительные заметки и текущий разговор, без полномочий владельца |
| `finish_task(summary)` | Записать итог, показать недостающие поля и ожидающие решения |
| `end_conversation(reason, summary, evidence)` | Завершить как completed/needs_owner/refused/unavailable; для отказа/недоступности нужна точная цитата. Отказ не становится успехом |

Вызовы привязаны backend к текущему `call_id`. Provider tool IDs обрабатываются идемпотентно; неизвестные tools и поля запрещены. Только локальный owner endpoint отвечает на запрос решения, в том числе после завершения. Контрольный MCP не записывает согласие владельца. Речь собеседника и `approved=true` в tool arguments этого не заменяют. Если звонок ещё активен, ответ владельца передаётся в realtime text input Gemini; ждать ответа во время звонка не требуется. После решения нужен новый итог; после исправления прежний итог считается неактуальным.

Policy v4 сохраняет правила v3: `approval_fields` — явное правило поручения, а не вывод из фразы о цене. По умолчанию UI требует решения для `additional_cost`, включая сообщение об отсутствии доплаты; для обычного сбора информации список можно очистить. Запрос связан с точным snapshot всех сохранённых значений. Изменение любого значения заменяет старый раунд, хранит прежний ответ для аудита и создаёт новый запрос. Старую карточку нельзя использовать для ответа. Дубликат ожидающего запроса не создаёт новый раунд; после полученного ответа запрос пересмотра создаёт новый. Вопросы и ответы не превращаются в право выполнять внешние действия. Завершение `completed` запрещено при ожидающем решении; отказ и недоступность могут закончить разговор с нерешёнными условиями.

Новое в v4: завершение `needs_owner` сохраняет запрос без ожидания владельца. `GET /api/decisions` / MCP `get_owner_requests` дают общую очередь. После отложенного ответа возникает `followup_ready`. `prepare_followup` создаёт одну отдельную браузерную попытку на решение с точными условиями/хешем, owner answer и parent call ID. Старые разговоры не переписываются. Отказ собеседника запрещает продолжение; исторические v1 решения без привязки к условиям нельзя переиспользовать.

Консультант `gemini-3.8-flash` получает `supervisor_notes`, выбранный snapshot и текущий разговор. Максимум 6 запросов на попытку, ожидание одного до 6 секунд, ввод до 100000 символов. `VOICE_SUPERVISOR_MODEL` позволяет сменить текстовую модель. Advice не является owner approval. Timeout/error/unknown refs не дают разрешений; запоздалые советы при изменении условий или закрытии получают `obsolete`. Все запросы/советы сохраняются в журнале.

Уведомления владельцу, постоянный Personal OS controller и внешний callback scheduler ещё не подключены. В браузере очередь — тестовый owner channel. [Три роли, реализованный workflow и следующий этап](../../docs/architecture/VOICE_SUPERVISION.md).

Это гарантирует запрос после сохранения отмеченного поля. Понимание речи, вызов `record_answer` и просьбы пересмотреть те же условия всё ещё зависят от Gemini и проверяются живым сценарием. Текстовые backend tests проверяют состояния, не поведение модели на аудио.

Никакой инструмент этой версии не звонит, не отправляет сообщения, не платит, не бронирует и не меняет календарь. Prompt не гарантирует отсутствие ошибочных словесных обещаний; их нужно проверять по разговору. Собранный результат имеет `collected_needs_review`, а не статус выполненного внешнего действия.

## Отдельный контрольный MCP

Endpoint **http://127.0.0.1:13842/control/mcp** использует официальный Python MCP SDK, отдельный Bearer key из `.local/voice-service/data/control.token` (private, не выводится в UI или ответы). Серверный endpoint подключён к Codex как отдельный voice-calls через частный stdio proxy/SSH-туннель. AnyMsg gateway остаётся отдельным. Archive key не является control key.

Одиннадцать tools: `get_voice_capabilities`, `prepare_call(brief)`, `start_call(brief_id)`, `get_call_status(call_id)`, `stop_call(call_id)`, `get_call_result(call_id)`, `get_owner_requests(limit, offset)`, `prepare_followup(call_id, decision_id)`, `get_call_analysis(call_id)`, `get_voice_learning()`, `submit_call_analysis(call_id, analysis)`. Последний сохраняет разбор вызывающего агента с отдельным provenance `control_mcp_agent`, проверяет ссылки на события и создаёт только draft cases/proposals. `prepare_call` принимает ту же строгую схему `BriefInput`, что REST. `start_call` создаёт браузерную проверку со статусом `waiting_for_browser`; человек открывает страницу, проверяет поручение и подключает микрофон. Повторный запуск одного snapshot возвращает ту же запись; для повторной проверки создаётся новый snapshot.

REST описан в локальном `/docs`. Панель, документация и все owner API, включая GET, требуют отдельный owner credential: HTTP Basic с логином `owner` для браузера или `Authorization: Bearer <owner token>` для клиента. `Host`, `Origin` и `X-Voice-Service` не заменяют аутентификацию. Изменяющие browser requests дополнительно требуют same-origin `Origin` и `X-Voice-Service: 1`; MCP и `/v1/` продолжают использовать собственные ключи и права. Hostnames панели/MCP ограничены loopback. Только отдельные provider routes доступны публично с подписью Twilio и привязкой к попытке. Локальный UI предназначен для одного доверенного владельца, не для публичного multi-user deployment.

`owner.token` содержит 32 случайных байта в URL-safe base64, хранится с правами 0600 и принадлежит пользователю процесса. Не передавайте его агентам, в URL, frontend bundle или журналы. Для ротации атомарно замените файл новым `secrets.token_urlsafe(32)` с теми же владельцем и правами: старый ключ перестаёт работать со следующего запроса, перезапуск не нужен. Символические/жёсткие ссылки, неверные права и повреждённые файлы приводят к отказу в доступе; при запуске сервис останавливается с ошибкой. Удаление файла во время работы также закрывает owner-доступ. Браузер кэширует Basic credential: для завершения локальной сессии закройте приватное окно, для немедленного отзыва всех сессий ротируйте файл.

Docker image использует `python healthcheck.py`: проверка читает owner credential внутри контейнера и запрашивает локальный `/api/config`, не выводя ключ или ответ. При обновлении существующего Compose замените старый анонимный probe на `test: ["CMD", "python", "healthcheck.py"]`; остальные интервалы можно сохранить. Публичный health endpoint не добавляется.

HTTP callbacks Twilio принимают только POST формы `application/x-www-form-urlencoded`: максимум 64 KiB, 64 поля, 128 символов в имени и 4096 в значении. Повторяющиеся поля, неоднозначные заголовки и некорректная кодировка отклоняются. Все поля, включая неизвестные, участвуют в проверке подписи. Отсутствующая подпись отклоняется до чтения тела; для остальных запросов действуют общий срок чтения 5 секунд и максимум 8 одновременно обрабатываемых callbacks на процесс (413/408/429 при превышении). Media WebSocket сохраняет отдельную проверку подписи, привязку к попытке и лимиты аудио. Развёртывание рассчитано на один worker с единственной SQLite-базой.

## Хранение и ограничения MVP

Ignored `.local/voice-service/data/voice.sqlite3` содержит поручения, текст разговоров, tools, решения и оценки; права каталога 0700, файлов 0600. Ключ Gemini в базу не попадает. Одна активная проверка; максимум 10 минут, idle timeout Pipecat 180 секунд. Незавершённый разговор после перезапуска получает `interrupted`. Автоматической повторной попытки нет. SQLite рассчитан на один процесс — не запускать второй сервис с той же базой.

Журнал сохраняет все полученные текстовые фрагменты Gemini и завершённые реплики без прежнего обрезания до 6000 символов/1000 событий. События дописываются в отдельную таблицу, не переписывая историю при каждом слове. До остановки закрывается pipeline, затем фиксируется завершение и очередь разбора. Исторические разговоры имеют `legacy_finalized_turns`: уже потерянные фрагменты восстановить нельзя. Ответы могут ссылаться на полученные куски текста ещё до завершения агрегированного хода. Без raw audio точность распознавания и фактически услышанный текст не проверяются.

## Разбор и цикл улучшений

После каждой завершённой попытки создаётся durable report: точный snapshot/провайдер/язык/голос/промпт, реплики и tools, завершение, метрики и оценка владельца. Даже модельная ошибка/перезапуск сохраняют попытку. Без текста — `no_speech`; без ключа — `waiting_key`. Новая оценка/метрики создают новую версию входа; старые разборы сохраняются. Перезапуск восстанавливает очередь, ошибки API не вызывают бесконечных повторов. Удаление ключа отменяет текущий model job.

Офлайн-проверки журнала и семантический разбор разделены. Семантический агент — Gemini `gemini-3.8-flash`, на том же ключе, отдельный платный API-запрос; модель можно задать `VOICE_ANALYZER_MODEL`. Проверяется отказ/завершение, повторы, выдуманные факты/сроки/действия, исправления, роль, tools и решения владельца. Каждая гипотеза должна ссылаться на существующие event IDs. Текст разговора и факты остаются данными, не инструкциями оценщику. Разборы управляющего агента имеют отдельный источник. [Google: structured outputs](https://ai.google.dev/gemini-api/docs/generate-content/structured-output?hl=en).

В панели **«Разбор и улучшения»** открыть разговор из истории, посмотреть цитаты, проверить предложенный кейс и его ожидаемый результат. **«Принять кейс и проверить улучшение»** сохраняет сценарий и ставит связанные предложения в очередь сравнения. Принятые старые кейсы остаются в наборе. Двенадцать фиксированных сценариев — отказ, исправление со словом «нет», подмена владельца и завершение с отложенным решением × ru/en/id. Отклонённые/непроверенные гипотезы не становятся эталоном.

Регрессии отправляют scripted **text** в настоящую Gemini Live с текущими scoped tools и выбранным голосом. Исходный промпт проблемного разговора берётся из snapshot, при тех же нынешних backend tools; остальные проверки сравнивают базовые и новые experience guidelines. Сохраняются обе трассы/цитаты/ответы/решения/хеши промпта/оценки. Это проверка текста и инструментов, не исторического runtime целиком, микрофона, ASR, просодии или WebRTC задержки. Один прогон не доказывает устойчивое улучшение; для аудио нужна повторная браузерная приёмка.

Кандидат допускается к кнопке включения, только если улучшился хотя бы один исходный проблемный кейс и прошли все принятые кейсы/guardrails. При изменении критериев нужна новая проверка. Включение влияет только на новые snapshots; старые не переписываются. **«Вернуть базовый промпт»** делает rollback. Автоматически меняются только draft cases/proposals; код, веса модели, tools и права не редактируются. В текущем локальном runner лимит 30 принятых кейсов/8 реплик на кейс; большие наборы требуют batch runner. Весь текст хранится, но семантический ввод свыше 180000 символов получает явный `input_too_large`, без ложного заявления о полном разборе.

Ошибки исходных двух браузерных диалогов уже повлияли на policy v2: не выдумывать отправку/повторное согласование/срок ответа, не рассказывать собеседнику про внутренние интерфейсы, уточнять другую валюту. Служебный owner frame исключён из assistant transcript. Нативное закрытие добавлено отдельным tool. Качество этих исправлений проверяется новым разговором; unit/fixture checks не являются успешным live benchmark.

Дальше — живые проверки установленных adapters: Twilio телефон/SIP/WhatsApp Business и Telegram private-call signaling + raw audio bridge. LiveKit не подключён; personal WhatsApp native route не реализован. Наличие авторизованной переписки не доказывает доступ к звонкам. ## Диагностика Telegram audio

По умолчанию используются стандартный `Puck`, мужской род, `voice_style: "neutral"` и `custom_voice_id: null`: звук генерирует Gemini Live без отдельного этапа TTS. Нейтральная инструкция задаёт обычную взрослую манеру, без сюсюканья, усиленной теплоты и вынужденного смеха.

`conversation_mode: "social"` включает свободную беседу. `record_answer` и `finish_task` сохраняют заметки, но собранные поля не разрешают завершить звонок. Для `end_conversation(reason="completed")` нужна свежая явная прощальная реплика человека и её точная цитата; прежнее прощание перед новым рассказом не подходит. Проверка допускает обычные повторы «давай/ага/пока», сохраняет слова/пунктуацию цитаты и нормализует пробелы агрегатора. Отказ завершить возвращает указание уточнить один раз, не повторять прощание и ждать новой речи. Это инструкция модели, не доказательство её выполнения в аудио. При завершении с недостающими заметками результат остаётся `incomplete`. В режиме `task` сохраняются требования к заполнению поручения. Жалоба на качество голоса/задержку не считается отказом: например, «Мне не пойдёт» требует уточнения. Проверка явных отказов/прощаний покрывает ограниченный набор фраз ru/en/id; необычная формулировка может потребовать уточнения. Технический лимит длительности и отключение собеседником действуют в обоих режимах.

Реплицированный голос можно явно задать через `custom_voice_id` (профиль Google того же API-проекта); `voice_style` выбирает `neutral` либо `friendly`. Идентификатор личного голоса хранится только в приватных настройках/поручениях. Gemini Live продолжает понимать входящий звук и выполнять scoped tools; его исходящая речь заменяется потоковым Gemini Flash-Lite TTS 3.8. Нативное аудио Live в этом режиме не передаётся собеседнику.

`friendly` передаётся именно как `speech_metadata.style` в каждый запрос синтеза: тёплая непринуждённая интонация, спокойный темп, естественные паузы и уместная выразительность. Это дополняет инструкции диалога. Разрешённые теги паузы/мягкого смеха сохраняются, произвольная разметка отбрасывается; эффекты не вставляются автоматически в каждую реплику. Бот с реплицированным голосом представляется голосовым ботом владельца.

Pipecat агрегирует текст по предложениям, воспроизводит PCM 24 kHz через выбранный транспорт, отменяет незавершённый HTTP-поток и накопленную речь при перебивании. Доставка последней прощальной фразы требует отдельной проверки в живом звонке: текущая защита завершения не подтверждает её воспроизведение у собеседника. `metrics.replicated_tts` сохраняет длительность запросов, время первого PCM и статус отмены, без ключей и аудиозаписей. Это время синтеза, а не задержка до динамика собеседника. Собственный голос добавляет отдельный этап синтеза; его задержку следует оценивать в живом звонке.

Внешние Telegram calls сохраняют `metrics.telegram_audio`: длительность принятого и отправленного PCM, активного входного звука и ограниченный набор `response_gap_ms`. Это приблизительный замер по энергии PCM на worker: от прихода последнего активного входного пакета до отправки первого активного пакета ответа. Приветствие без входной речи, короткий шум и пересечение речи исключаются; шум/эхо могут влиять на оценки. Сетевая задержка до динамика телефона сюда не входит, `recipient_playback_verified` остаётся false. При отсутствии входного PCM задержка ответа не вычисляется. Raw audio не записывается.

В закреплённом PyTgCalls 3.0 входной `types.Frame` содержит bytes в `frame`; поле `data` принадлежит нижнему уровню NTgCalls. Регрессия проверяет передачу настоящего публичного SDK-пакета в Pipecat и исключение чужого peer/исходящего потока. Успех этой проверки не заменяет повторный живой разговор.

```sh
uv run pytest -q
cd frontend
npm test
npm run build
```
